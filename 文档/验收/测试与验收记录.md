## 正式游戏接入后验收

下表为正式游戏接入后的验收条件。溪谷示例使用加速计时和简化交互，正式的存档恢复、内容条件与大地图性能在游戏接入后验证。

| 场景 | 预期结果 | 主文档 |
| --- | --- | --- |
| 收获一株，把其中一份拿去做饭 | 主、副、概率产出先统一入包；出售、留种、加工、交付按实际数量扣减。背包满时清出空间可重试，产出稳定 | [土壤与经济](../策划/土壤与经济.md) |
| 同一产物收出两种颜色 | 同品质合堆，只计一件收集对象。颜色对照用于检验美术，商品、任务、配方和稿酬均认同一标识 | [物种与收集](../策划/物种与收集.md) |
| 新档复原稀有种，再完成首条用途，耗尽库存并读档 | 复原取得种源、记录发现；可用产物入包时才开始倒计时。按期完成指定用途时点亮、付一次稿酬。跨霾日与读档保留品质和途径，再做同用途不重领 | [物种与收集](../策划/物种与收集.md) |
| 截止前开工，恰在截止时或之后完工 | 照常获得成品，指定成品可首次收录；源条目仍只记发现。再取得一份合格原料可重开倒计时，拿旧半成品完工仍无法点亮；用新批次按期完成则点亮一次 | [首次上锚倒计时](../策划/物种与收集.md#43-首次上锚倒计时) |
| 取得第二份新原料，带倒计时进日结并存读档 | 新原料沿用本轮截止时刻。午夜、离线与翻页均不扣时间；确认次日后继续活动，倒计时和加工同步续算 | [首次上锚倒计时](../策划/物种与收集.md#43-首次上锚倒计时) |
| 23:59 种下作物、留一件在制品，高倍率走到午夜 | 只累计最后 1 活动分钟，留在当天日结；翻页、停留、保存再读档均保留文案页、作物进度和加工剩时。连点确认仅刷新一次，次日 06:00 起继续 | [时钟季节与天气](../策划/时钟季节与天气.md) |
| 采野莓、捕鱼、收蛋、制果酱 | 前三种取得行为只记发现或来源。野莓制酱点亮野莓及指定果酱条目，鱼和蛋的来源动物须分别完成其用途。相同条目跨区域只算一次 | [分册规则 §7](../策划/物种与收集.md) |
| 成熟果留田跨风日、霜日 | 风后可采数量保持原值。温度未达致死条件的未覆盖果实在霜日按物种改品质；暂停后真实时间再长也不触发，采收入包锁定品质 | [天气 §6](../策划/时钟季节与天气.md) |
| 正式测试面板调用游戏时钟与钱包 | 手动步进停在日结，确认次日只执行一次日事件；测试加款只增加余额，读回存档金额一致，稿酬与任务进度保持原值 | [时钟与存档架构](../开发/时钟与存档架构.md) |
| 分别给一份花生和三蒴芝麻留种 | 按示例得 2 粒、144 粒；种数预览与入包一致。背包满时可重试，原料和种子不重复扣发 | [留种机制](../策划/土壤与经济.md) |
| 同日把露天温度从 1°C 降至 0°C，再降到 −1°C | 辣椒在 0°C 停长，−1°C 冻死并失去挂果；菠菜低于零度停长，回暖后接续进度；维持适温、适季的温室辣椒继续生长 | [跨季规则](../策划/时钟季节与天气.md) |
| 汇总区域自然来源，检查每季行程 | 多区同物种去重，跨季可得者不计专属；专属数 × 2 ≥ 生物物种总数。逐季可找到农事以外的采集、余绪、钓点或矿点 | [季节与年](../策划/时钟季节与天气.md) |
| 两种矿石可炼同种锭，指定使用线以建炉为终点 | 炼锭只记成品；用其中一批锭建炉时只点亮实际消耗的矿石。再建、读档或日结都不重发首笔稿酬 | [使用线](../策划/物种与收集.md) |
| 建屋后寻路，在咬钩或挥镐时跨午夜 | 角色绕开建筑并能到门口。日结停住动作和输入窗口，恢复时复验目标；一次有效收竿或采尽矿点只给一份结算 | [场景实现](../开发/时钟与存档架构.md) |
| 磨坊开工后走到河岸，回来前跨过午夜日结 | 农场绘制节点卸载后，磨坊只在活动时间内继续加工。返回时显示正确进度；日结停留期间，加工时间和田间状态不变 | [区块加载](../开发/时钟与存档架构.md#62-区域区块与玩法点位) |
| 更换作物插画 | 更新资源清单即可替换同一阶段图。田间、背包和存档使用同一物品标识；形状、配色和资源版本可独立调整 | [美术规范](../美术/作物与物品美术规范.md) · [加载方案](../开发/时钟与存档架构.md) |

首批种植循环接入后，记录正常流速下第一次辨认中期、收获、上锚和买地的实际游戏时长，用于修订种植和经济数值。

# 物志 · 作物与物品 SVG 美术规范

v0.1 讨论稿，适用于田间植株和背包收获物。当前原型使用 100 × 100 的 SVG 画布，提供 32 px 预览。

## 每种作物先选一个值得记住的形状

开画前，把它和最容易认混的作物放在一起。先用一句话说清楚玩家凭什么认出它，再决定用什么工具画。主特征优先占据外轮廓或大块留白；叶脉、果点、种子等细节负责近看时的质感。

| 对照对象 | 第一眼看什么 | 放大后补什么 |
| --- | --- | --- |
| 红苹果、黄苹果 | 同一对圆肩、顶部果窝、短柄；两者沿用一个苹果轮廓 | 果皮色板可用于原型对照 |
| 苹果、橘子 | 苹果顶部内凹；橘子较扁，背包构图前方错开一瓣，形成第二层轮廓 | 果窝阴影、橘皮油点、瓣膜 |
| 西瓜、南瓜的中期植株 | 西瓜藤沿地面横向延伸，叶片深裂；南瓜的宽叶由粗长叶柄托起，叶下留出空隙 | 卷须、叶脉 |
| 茄子、辣椒的收获物 | 茄子末端膨大、重心偏下；辣椒收成向侧面弯曲的长尖 | 萼片形状、果皮高光 |

## 三种画法均可交付

按**作物和阶段**选画法。一种作物可以同时采用三种，最终都要能导出独立 SVG。

| 画法 | 何时用 | 例子 |
| --- | --- | --- |
| 共用底图，替换色板 | 同一产物需要不同外观 | 红苹果和黄苹果共用果形和生长图，到结果时换果色 |
| 共用局部，单独编排 | 局部可以复用，辨识度主要来自部件之间的位置、数量和方向 | 豌豆复用小叶，独立安排成对叶序、攀援茎和梢头卷须 |
| 专属 SVG 路径或整图 | 大轮廓、关键姿势或遮挡关系决定物品身份 | 香蕉果把的前后关系可以整幅绘制；洋葱出土的弯钩只需一条专属曲线 |

只有一个物种用到的形状，可以直接写进它自己的绘图函数或 SVG 文件。等另一个物种确实需要同一部件，再提取共用画法。遇到两张图趋同时，优先改那张最缺乏特征的图，避免为了一个特例改动整套生成器。

## 从出土到采收

| 画面 | 玩家要读出的信息 | 绘制约定 |
| --- | --- | --- |
| 刚出土，可选 | 已经发芽，种植有进展 | 允许相似作物共用芽形。洋葱弯钩、小麦抽针等有鲜明特征的作物可以单画 |
| 幼苗 | 种下的作物开始显出特征 | 选第一批有辨识度的叶已经展开的时刻。用叶形、叶数、夹角或出叶方向建立特征 |
| 生长中期 | 它正以怎样的方式生长 | 至少画出一种可见的结构变化，如抽藤、分枝、分蘖、莲座扩张或叶鞘拔高。相邻两帧保留主茎走向或基部位置 |
| 田间成熟 | 此时可以采收 | 果实连在枝上，瓜落在藤旁，根菜可露根肩。叶用作物可用叶丛饱满度、结球等特点表达成熟 |
| 背包收获物 | 采到的是什么 | 重新取景，让采收部位占据画面。允许用成串、带苞叶或带一瓣的构图表现物品；田间仍用完整、连生的形态 |

每个相邻阶段都值得先看一眼剪影。比如西瓜从短苗变成向一侧伸展的爬藤，即使果实尚未出现，也能读出生长进度。当前原型从幼苗开始；“刚出土”是后续玩法可选的一帧。

## 统一的交付约定

- **画布与锚点。** 使用透明背景和 `viewBox="0 0 100 100"`。田间植株以约 `(50, 89)` 为根部定位点；爬藤可从附近偏向一侧伸展，多帧保持同一个着地点。收获物按视觉重心居中，成串或斜放的物品可采用不对称构图。描边与叶尖都留在画布内。
- **光与线。** 默认左上受光，右下较暗。外缘用物体本色的深色，层叠处用明暗交代前后。主轮廓与大的明暗面承担 32 px 下的阅读，细纹可以在缩小时消失。
- **外观与品质。** 试色属于同一产物的美术表现。红、黄苹果仅为造型讨论示例；同品质同物品合堆，交付稿不增加收集条目。品质由背包格的边框或角标表达，保留物品本色。灰度下允许红、黄苹果看起来相同。
- **独立文件。** 交付 SVG 自带路径、色板和所需渐变，能在空白页面单独打开。去掉背景卡片、文字、外部图片和字体依赖。多个 SVG 同屏时，渐变和裁切引用应指向各自图内的定义。

## 交给游戏的文件

保留可编辑的源图或生成参数，美术验收后导出独立透明 SVG。每个阶段使用清楚的中文文件名，游戏通过稳定的资源键取图。普通植物交幼苗、中期、成熟和收获物；多年生另交休眠帧，出土帧按需要补充。停长保留当前阶段图并显示停长标记；休眠显示休眠帧，存活挂果株优先显示成熟图。冻死显示枯株并撤去可采标记，须能与可返青的休眠株区分。鱼、矿石、果酱等按各自画面交付所需图。加工配方与物种色板都可以共用一张成品图。

同一页用一株部件组合的豌豆和一幅专属果树图对照验收：各阶段对齐、32 px 清楚、独立打开完整、重复摆放无渐变串色。游戏的清单格式、加载时机和缺图处理见[时钟与存档架构](../开发/时钟与存档架构.md)。

## 场景与动作资源

建筑图标出地基占地、门口交互格与遮挡屋檐；角色各姿势共用脚底锚点。钓鱼交抛竿、持竿、收线姿势和可单独定位的浮标；挖矿交挥镐姿势、握点及矿石裂纹阶段图。地形贴图、水波、浮标和矿石可以复用 SVG，位移、旋转和层叠交给浏览器。碰撞、咬钩和命中的判定见[场景实现](../开发/时钟与存档架构.md)。

## 一张新作物的制作卡

用五行文字记录关键决定即可。以豌豆为例：

| 项目 | 填写示例 |
| --- | --- |
| 最近似的作物 | 葡萄，两者都会攀援、长卷须 |
| 区分线索 | 豌豆的细叶轴两侧成对长小叶；葡萄的一片掌状大叶占据较大的色块 |
| 分阶段构图 | 幼苗先露一组复叶；中期茎节升高，叶轴末端卷起；成熟时豆荚沿节位下垂 |
| 背包取景 | 单个豆荚斜放，打开一侧，露出一排圆豆；藤上仍挂闭合豆荚 |
| 绘制选择 | 小叶复用，叶序和茎节按阶段配置，打开的豆荚使用专属路径 |

## 放进游戏前怎么看

1. **同阶段横向比。** 把目标作物和最容易混淆的两三种作物并排，先遮名字，在 32 px 彩色和灰度下各看一次。隔一会儿再自己辨认，记录具体认混的一对。优先调整叶形、构图或留白，再补纹理。
2. **同物种纵向比。** 连续切换幼苗、中期、成熟，看根部是否跳动，中期出现的新结构是否清楚，可采收部位是否合理。把背包图放在末尾，看能否和田里的采收部位对应起来。
3. **回到真实场景。** 在游戏实际田块和背包底色上按最终尺寸查看。物志的浅色底和放大图用于检查细节；绿叶融进田地或浅色果实消失在格子里时，优先调轮廓明度和遮挡关系。

第一次扩充物志时，先找一组容易混淆的近似物种走完这三步，再决定哪些部件值得批量复用。

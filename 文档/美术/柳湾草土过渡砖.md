# 柳湾草土过渡砖

草地与裸土之间的一整套过渡地砖，32×32 源像素、固定左上受光。五种形状：直边、外角、内角、斜切内角、斜切外角，各 3 个变体。全部由 Python + Pillow 生成，没有手绘、没有抗锯齿。

过渡两侧的纹理不是重画的，而是**直接调用** [草坪生成器](../../prototype/pixel-farm/grass-generate.py) 与 [裸土生成器](../../prototype/pixel-farm/soil-generate.py) 的 `build()` 取原块，再按边界掩码叠合。所以色板、密度、像素粗细与原块天然同源。

## 三种形状

以草为基准（草在左上），掩码由两个判据组成：`above`（在横边界之上）与 `left`（在竖边界之左）。

```
直边：草 = above            外角：草 = above 且 left     内角：草 = above 或 left
┌──────────────┐            ┌──────────────┐             ┌──────────────┐
│   草  草  草 │            │   草  草 │ 土 │             │   草  草  草 │
│   草  草  草 │            │   草  草 │ 土 │             │   草  草  草 │
│──────────────│            │──────────┼──│             │──────────────│
│   土  土  土 │            │   土  土 │ 土 │             │   草 │ 土  土 │
│   土  土  土 │            │   土  土 │ 土 │             │   草 │ 土  土 │
└──────────────┘            └──────────────┘             └──────────────┘
```

- **直边**：草 516 像素 / 土 508 像素。
- **外角**：草只剩左上象限（281 像素），其余是土。
- **内角**：土只剩右下象限（273 像素），其余是草。

## 斜角砖（45°）

### 斜线落在哪

斜线取 `y = x + 16`：从左边中点 `(0,16)` 走到下边中点 `(16,32)`。两个端点正好是直边砖边界落在砖边上的位置（左边缘 y=16、下边缘 x=16），所以斜切角能和直边砖直接对接。

另一条常见的做法是对角到对角（`(0,0)→(32,32)`，草土各 496 像素）。那条线的端点在砖**角**上，只能和另一条 45° 线相接，永远接不上直角直边——它只能拼菱形田，拼不了方田倒角。所以这里用的是中点线。

### 用法二：45° 斜边

斜边不能只靠一块：同一条 45° 线穿过方格时，在相邻的砖里截出的三角在**对角**上，所以两块要相间排列。逐砖算局部截距（`c` 是斜线在全局坐标里的截距）：

```
d = c + 32 × (gx − gy)
d = +16 → bevel-inner 原样
d = −16 → bevel-outer 转 180°
|d| ≥ 32 → 整块草 / 整块土
```

`edge-diag-strip-4x.png` 是单条斜边，`edge-diag-band-4x.png` 是斜向土带——土带下边界「草在下」，用的是两块对调（`bevel-outer` 原样、`bevel-inner` 转 180°），同一套砖两条边界都铺得出来。

## 画法

1. **取原块**：`GRASS.build('lawn', v, region=..., count=...)` 与 `SOIL.build('bare', v, region=..., count=...)`。给生成器传了可见区域和簇数，纹理就只落在各自那一侧，且密度按面积换算。
2. **边界轮廓**：受约束的随机游走。相邻列最多差 1 像素，振幅不超过 ±2，两端都停在 0。两端归零是硬要求——直边砖横向相接时，两块砖的边界必须等高才能连成一条线。斜角砖不用随机游走，直接取 `y − x = 16` 这条固定斜线：斜切角要读成刀切，不能被抖动成圆角。
3. **叠合**：按掩码逐像素取草或土，然后把紧贴边界的土像素回到底色，避免被切掉一半的土粒留下碎片。
4. **草根线**：所有朝土一侧的草像素改成深橄榄绿，形成连续 1 像素的根线。只在草这一侧加，土这一侧不动，所以交界是贴地的，不是抬高的田埂。
5. **草尖**：沿边界挑两三处，往下探 1~2 像素深橄榄绿，读作稀疏草尖伸进土面。斜角砖的"朝土方向"逐点不同（草 7/8 的砖朝左下、草 1/8 的砖朝右上），所以走的是每个草根像素实际的土邻居方向，不是一律往下。
6. **环绕**：横向按环面取模（直边砖要能左右相接）；纵向、角砖、斜角砖都不回绕——过渡砖两端分属草区和土区，回绕会在地砖边缘画出一条假根线。

## 校验

```sh
python3 prototype/pixel-farm/edge-generate.py --verify
```

| 判据 | 要求 | 实测 |
| --- | --- | --- |
| 六色锁定 | 不出现六色之外的像素 | 15 张全部通过，色数 = 6 |
| 草根线连续 | 边界上每个草像素都是深橄榄绿 | 15 张 0 处断裂 |
| 直边可拼接 | 左边缘与右边缘的草行数相同 | 全部 16 行 |
| 斜边斜率 | 逐行草像素数必须恒定地每行差 1 | bevel-inner `[-1]`、bevel-outer `[1]` |
| 纹理密度 | 与原块相差不超过 ±50%（小面积取样方差大） | 草 5.7%~10.5%（原块 8.5%），土 9.2%~22.3%（原块 15.4%） |
| 装配一致性 | 装配图里所有"草像素贴土"都是深橄榄绿 | 四张装配图均 0 处违反 |

装配预览比单砖更能说明问题：`edge-assemble-soilpatch-4x.png` 与 `edge-assemble-grassisland-4x.png` 里如果某个角用错旋转，会出现土从草中间穿过去、或者草岛裂成几块——这两张都是完整的。

斜角砖的旋转错误**只有拼起来才暴露**：单块自检时每块自己的草根线都是对的，转错了也照样对。所以两张斜切装配图加两张斜边图都过了同一道 `seam_faults()` 检查——跨砖逐像素找"草直接贴在土面上"的位置，四张全为 0。

只有 `bevel-inner`（土只剩 136 像素）和 `bevel-outer`（草只剩 136 像素）的小三角侧跳过密度判据：一百多像素里 2 颗土粒和 3 颗土粒就能差出 50%，比值没有意义，最终以装配图目视为准。

## 调参

改 `edge-generate.py` 顶部即可：

- `VARIANTS`：每个形状出几个变体，现为 3。所有变体共用同一条边界轮廓，只换纹理，所以任意变体都能互相拼接。
- `MID`：边界位置，现为 16（草 16 行、土 16 行）。改成 12 就是草窄土宽的过渡。斜角砖的斜切腿长也等于 `MID`，改小就是更小的倒角、改大就是更重的切角。
- `diag_mask()` 里的 `y - x >= MID`：改成 `>` 会把整条斜线挪 1 像素，接直边砖时就会出现 1 像素台阶，不要随手改。
- `meander()` 里的 `amp`：起伏幅度，现为 2。改成 1 更平，改成 3 会出现 3 像素深的缺口。
- `meander()` 里的 `r < 0.2 / r > 0.8`：走向概率。放宽到 0.4/0.6 会更碎、更锯齿。
- `fringe()` 里的 `tips >= 3`：草尖数量上限（斜边用 `fringe_diag()`，同一个上限）。
- `compose()` 里的 `g_min / s_min`：小面积侧的纹理下限。斜角砖的小三角只有 136 像素，下限降到 1；调回 2~3 会糊成一团。

## 踩过的坑

- **环面回绕不能乱用**。草根线一开始对四个方向都取模，结果地砖顶行被当成"贴着下方土区"，在砖顶画出一条假根线；角砖左缘也被自己的右缘判成贴土，长出一条 18 像素的竖线。现在的规则是：只有直边砖横向回绕。
- **轮廓钳制不如直接生成**。先平滑再钳制相邻差，钳制本身会在端点制造跳变，出现 5 像素高的竖墙。改成受约束的随机游走（每步 -1/0/+1，剩余步数不够回家就往 0 走）后，天然满足"相邻差 ≤1、两端为 0"。
- **两条边不能各用一条随机轮廓**。角砖竖边如果换一条独立的轮廓，接上旋转后的直边砖时会错开 1~2 像素。现在横边竖边共用同一条。
- **计数要以"已放置数"为准**。草簇先按间距选中心、再检查母题是否越界，两者分开写会导致越界的簇被丢弃而数量不足，小面积角砖因此几乎没草。合并成一个循环后才守住密度。
- **小面积区域的密度只能看趋势**。角砖的草地只有 280 像素，2 簇与 3 簇就能差出 40%，所以判据放宽到 ±50%，最终以装配图目视为准。
- **斜角砖不能用对角到对角那条线**。一开始想省事，用 `(0,0)→(32,32)` 的贯穿线，草土各 496 像素、一块砖走一路。但它两端落在砖**角**上，接直边砖时边界根本对不上——端点必须落在 `MID`（砖边中点）才能和直角直边咬合。
- **两块斜角砖是互补，不是旋转**。草 7/8 和草 1/8 既不是旋转关系也不是镜像关系之外的关系，只能出两张图；想用一块转着拼，第二条边界就会错位。
- **整数像素判据在旋转后会差 1 像素**。`y − x >= 16` 转 180° 变成 `x − y >= 16`，跟"同一根线另一侧"的 `x − y >= 17` 差一个像素。这个差**不出现在砖缝上**（缝两侧的判据都来自各自砖内的同一条阶梯，接得上），所以判据留在逐砖定义，验证交给跨砖的 `seam_faults()`，而不是去追那 1 像素的数学一致性。
- **斜边的草尖不能一律往下长**。草 1/8 的那块砖，朝土的一侧是右下，照抄直边的"往下探"会把草尖扎进自己的草里。按每个草根像素实际的土邻居方向走才对。

# 农场视觉样板制作计划

## 目标与已确认条件

先完成一块可操作、可扩展的小农场，验证草地、裸土、土路、耕地、作物和人物放在一起是否清楚、协调。此计划不表示所有美术方案已经验收。

已确认：基础地格 32×32 源像素，普通作物种植单元 64×64，占 2×2 基础地格，根部株距和行距均为 64；一单元一份作物，一次播种、一次收获。樱桃萝卜田间图为 48×72。素材尺度、可耕单元和碰撞分别定义，详见[像素美术与素材样板](像素美术与素材样板.md)。

场景配色与空间表现也已确认：河畔青绿、Canvas 2D、固定视角、「光影与田畦」模式、默认 4 源像素土壁，左上光源和右下投影，不引入 Three.js。以下阶段中的比例、地面过渡、操作与性能仍需继续验证；季节天气为待实现方案。

## 第一阶段：比例与视觉基准

先在一块 4×3 种植单元的试验田里摆放白菜、人物占位、两种宽度的通道及简化建筑地基，再画完整素材。

- 固定源像素密度与整数倍显示，按实际窗口检查能同时看到多少种植单元。2 倍时每个种植单元显示为 128×128 CSS 像素；视野大小必须真实可用。
- 复核人物与白菜的比例。当前占位人物不是最终比例，不能让较高的白菜无意间比成年人更高；可以调整人物尺寸与造型，不能为塞进旧画面而任意缩小已选择的白菜。
- 检查作物的俯视倾角、地面视角和脚点关系。当前原图较接近正面，要在地面上验证是否像扎根生长，再据此约束后续生图；像素化不会自动修正透视。
- 确定一份风格参考、左上受光、场景共用色板、明暗层次和轮廓做法。现有白菜的 16 色是该素材的处理参数，不是全场景只能有 16 色。
- 新地形直接制作 32×32 源像素版。旧样板将 16 像素地面放大两倍仅供实验；正式素材不能在不知情的情况下混用不同粗细的像素。

产物：比例标尺场景和视觉基准记录。先确认草地能衬托白菜、人物与田块看起来合理，再进入成套制作。

## 第二阶段：地面与过渡

| 内容 | 首批交付 | 验收重点 |
| --- | --- | --- |
| 草地 | 安静底纹 3–4 个变体，草簇单独做 | 大面积平铺没有明显棋盘重复，不用密集小草抢作物注意力 |
| 裸土 | 普通未翻耕土 2–3 个变体 | 与道路、翻耕土能区分；裸土外观本身不决定是否可开垦 |
| 土路/田埂 | 一套踩实土路，草土边缘与转角 | 与可种植区域分开，横竖路宽一致，角色能到达操作位置 |
| 干耕地 | 连片翻耕纹理、边缘和转角 | 单块、长条、矩形、L 形、T 形及中间缺一块均能拼接 |
| 湿耕地 | 与干耕地结构对应的深色版本 | 作物遮挡后仍能看出浇水状态；不只依靠细小闪光表达 |
| 地形连接 | 草/裸土、草/土路、草/耕地，以及干湿相邻 | 包含内角和外角，不能只画一张四边都有草的封闭地块 |

地面优先用程序控制纹理、连接形状与边界；AI 可以提供风格参考或可用底纹，经过统一处理后接入。不要直接拼一批彼此带光影、透视或封闭边框的 AI 方块。

渲染与逻辑分开：地表可以按 32 像素格拼接，播种、湿度与收获按 64 像素种植单元管理。相邻种植单元的土纹可以连成一片，鼠标指向时只高亮当前 64×64 单元。

## 第三阶段：耕作状态与反馈

首批要表现：未开垦、可开垦、已翻耕未播种、已播种、幼苗、中期、成熟、收获后空耕地；浇水作为可叠加的土壤湿度表现。播种可以用独立小穴或少量种子标记，避免空土和刚种下完全一样。

- 成熟作物继续保留田间造型，选中或靠近时补可采提示，不持续给每株加大标签。
- 湿度可用地表深浅分档表现，点击或选中时读取精确值。现有土壤设计中的养分、pH、菌群健康在土壤面板中明确显示，不把四种属性全部叠成地面花纹。
- 土壤状态归属于一份种植单元；不能因为底层拆成四个基础格，出现同一株作物四套不一致的湿度或重复结算。后续正式接入时需对齐旧文档中“每格地”的含义。
- 选中框、可播位置、不能操作的原因、根部交互点和角色站位独立绘制；不能用植物透明留白决定能否点击。
- 保留未来枯死、停长、休眠、肥料和地脉叠加层接口，首批不要求做完所有图；现有午夜与暂停规则继续适用。

## 第四阶段：作物与场景骨架

柳湾已接入樱桃萝卜的四个田间阶段和背包图。后续可用胡萝卜、番茄和小麦验证不同体型。生长阶段沿用各自画布与根部锚点，统一 64 像素株行距，小苗不放大、支架不乱跳，小麦可用一簇代表一份种植作物。

场景继续补一棵柳树、普通石块、河面与裸土岸线，并用现有围栏和小屋占位验证比例。开局使用线优先补樱桃萝卜、旧盐坑的岩盐矿点、盐灶和腌菜瓮。角色需要基本四向移动，用脚点排序验证作物和树木遮挡。小栈桥、芦苇和浮标可在布置钓点时加入。

地表 → 土壤湿度 → 脚底阴影 → 按脚点排序的作物/人物/建筑 → 树冠与屋檐 → 选择与交互提示 → 普通界面。通道宽度、作物能否穿行和操作距离通过样板测试后再定，不通过图片尺寸直接推断。

### 水面与河岸

- 水面用 32×32 源像素的可平铺底纹，建议先试低细节青蓝底色和短水纹，后续可单独叠加水波动画。
- 岸线只交付裸土与水面的过渡。首批做直边、内角、外角及所需朝向。土的一侧沿用现有裸土色板，可在贴水处加一线稍深的潮土色，水的一侧可用浅青色表现浅水。
- 地图从水到内陆依次为水面、裸土岸和草地或耕地。裸土在转角、窄处和区块接缝也要连续，土路在裸土岸汇入。单独验收凹弯、凸弯和斜角处的水陆接缝。

### 普通石块与矿点

- 试作采用同一块灰褐色岩石底图。普通石头使用底图，矿点在岩面上叠加与岩体咬合的彩色凸起。凸起沿用左上受光，用亮面和暗面画出厚度。
- 矿种通过颜色、凸起形状或纹路区分。首批先做普通石头与岩盐矿点，用米白或浅粉的棱角晶簇试作岩盐。保持精灵画布、落地锚点和占地一致。
- 地图里画矿点整块岩石，背包里另画采下的矿物图标。接入挖矿反馈时，再补裂纹与采尽状态。

## 第五阶段：完整小样板验收

建议首块试验田采用 4×3 种植单元，旁边有草地、裸土、土路、通道、人物和少量物件。提供以下对照：

1. 空地与满种；干地与湿地；同类连片与混种。
2. 单块、长条、拐角、缺口和干湿交错，检查拼接与重复。
3. 白菜成熟与幼苗同时出现，隐藏名称后辨认四种作物。
4. 人物走到每个种植单元旁边，检查遮挡、选择目标及路径。
5. 按游戏尺寸查看，切灰度、整数倍和窄屏，确认轮廓、湿度与提示可读。

随后接一个最小操作循环：翻地 → 播种 → 浇水 → 切换生长阶段 → 收获。若暂用手动切阶段而非正式游戏时钟，应在样板中明示，不能声称已接入完整生长系统。

通过后才扩展首区地图、四季版本、天气、更多作物、建筑与动画。

第一批搭配已选定河畔青绿与光影田畦。当前统一入口为[农场样板](../../prototype/pixel-farm/index.html)，未采用的比较 demo 已清理。接下来精修过渡、播种小穴及耕作反馈；季节天气对照按独立提案分批推进。

# 时钟、季节与天气

**状态**：v0.1 框架
**范围**：时间模型、日边界、季节与年、生长档位、天气与预报
**不包含**：具体物种的生长天数（见物种表，待定）

---

## 1. 时间模型：激活计时

时间只在**页面可见、有焦点且未手动暂停**时推进。

| 条件 | 行为 |
| --- | --- |
| 可见、有焦点、未暂停 | 推进 |
| 切标签页 / 最小化 / 失焦 | 自动暂停 |
| 手动暂停（空格） | 暂停 |
| 关闭页面 | 时间静止，无离线结算 |

**状态指示**：顶部常驻一枚状态灯，二态显示 `▶ 第 N 天 · HH:MM` / `⏸ 时间静止`。必须始终可见，避免玩家误判。

**存档**：随时可存，无冷却。存全量快照，不存增量。

**由此排除的设计**：无离线结算、无 catch-up 模拟、无时间冻结机制、无回归弹窗。

---

## 2. 一天

| 项 | 值 |
| --- | --- |
| 一天时长 | **18 分钟前台激活时间（正常流速）** |
| 一天跨度 | 06:00–24:00 为活动时段，午夜直接进入次日 06:00 |
| 换算 | 1 游戏小时 = 1 现实分钟；**1 游戏分钟 = 1 现实秒** |

**时间纯自然流逝，动作不额外扣时间。** 不做"种一株扣 5 分钟"这类行动税，否则会退化成行动预算制，与随时暂停的松弛感冲突。

00:00–06:00 作为叙事上的休息时间。玩家保留地点、操作和进行中的工作；23:59 后再走 1 游戏分钟即显示次日 06:00。跳过的六小时不给作物、加工、冷却额外进度。通常夜间窗口设在 18:00–24:00。流速测试只调推进倍率。

---

## 3. 日边界：软刷新

**没有睡觉机制。** 06:00 不中断、不结算、不强制回家。

日边界只做一次静默刷新，顺序固定：

1. 天气推进（按预报表翻页，不做随机重掷）
2. 商店换货
3. 委托板刷新
4. 月相推进
5. 动物产出结算
6. 土壤湿度与肥力恢复一档
7. 刷新余绪显形条件

**表现**：顶部飘一行极轻的提示（`第 N 天 · 天气`），不阻断操作、不弹窗、不暂停。玩家可以连续跨过任意多个日边界。

## 4. 季节与年

| 项 | 值 | 现实耗时 |
| --- | --- | --- |
| 一季 | 28 天 | 8.4 小时 |
| 一年 | 112 天（4 季） | **33.6 小时** |

按正常流速，常规作物的 5–9 个足速生长日约需 90–162 分钟前台时间。季节规划遵循以下约定。

- **季节锁只用于调味，不用于卡内容**。第一幕四区的核心物种必须跨 2 季可得。
- 季节专属物种占总量的比例上限：**20%**。
- 避免出现"这个季节没东西可收集"的空窗期。

## 5. 生长档位

| 档 | 天数 | 特征 | 是否跨季 |
| --- | --- | --- | --- |
| 速生 | 1-3 | 叶菜、葱类、竹笋 | 否 |
| 常规 | 5-9 | 茄科、瓜类、豆类 | 否 |
| 长程 | 12-18 | 禾谷、块茎、鳞茎 | 否 |
| 跨季 | 32-40 | 越冬型谷物与纤维作物 | 是，跨 1 季 |
| 多年生 | 足速下首次成熟 ≤28 天，之后按季反复结果 | 果树、藤本、灌木浆果 | 植株跨季保留 |

**硬约束**：

1. **足速生长所需时长上限为 40 天**（每天 1,080 活动分钟；季节停滞或减速会延长实际等待），远小于一年。不存在"需要养一年才长大"的物种。
2. **多年生作物（果树、藤本、灌木浆果）移栽后必须在 ≤28 天内进入结果期**，在满足生长条件时结果。禁止"先养两三年再结果"的设定。
3. **结构性保证**：每个区域必须覆盖四季各有可结果的多年生物种。这样无论玩家何时进入该区，当季都有多年生作物产出，不存在"要等一整年才看得到它结果"的情况。
4. 跨季档作物（32-40 天）因播种时间较晚，日历上可能落在跨年的位置，但**成因是播种时机，不是成长周期**，不构成"漫长"。这类作物只在适季播种才有全额收益，播种窗口本身就是玩法。
5. 竹为速生档，割后再生，不作为多年生处理。

**一句话口径**：不允许"成长周期长"的物种，只允许"播种窗口窄"的物种。

### 跨季规则

每个物种标注「适季」与「耐季」：

| 所处季节 | 生长速率 |
| --- | --- |
| 适季 | 100% |
| 相邻季（耐季） | 50%，不死，仅减速 |
| 非耐季 | 0%，完全暂停，本体保留在地里 |

季节切换本身只改变后续生长速度。成熟果实优先保留在枝上；采完后，多年生植株再按季节进入再生或休眠。霜效单独按天气规则结算。

## 6. 天气

### 6.1 设计原则

**每种天气都必须是一个内容窗口，不能只是惩罚。** 玩家的时间不应被固定在种地一件事上——天气要成为调度钓鱼、采集、挖矿、加工的理由。

### 6.2 八种天气

| 天气 | 对环境的作用 | 独有产出类别（内容由物种表填） |
| --- | --- | --- |
| 晴 | 基准；蜂活性高 | 蜂产品增量、晒制与晒盐效率提升 |
| 阴 | 生长 -10%，蒸发减弱 | 阴生菌类 |
| 雨 | 免浇水，湿度回升 | 环节动物类鱼饵、雨后菌群、雨水收集 |
| 雾 | 蒸发归零，光照不足 | 雾生菌、稀有昆虫、鱼类稀有度上浮 |
| 风 | 推动风力设施，改变环境表现 | 风力加工、候鸟观察；田间作物的数量、品质、收获方式均保持原值 |
| 雷 | 有几率损坏露天设备（可预防） | 雷击木类建材、雷雨菌 |
| 霜 | 在田作物按配置结算品质变化，覆盖可防霜 | 喜霜作物可升质，霜敏作物可降质，中性作物保持原品质；产量保留 |
| 霾 | 蠹蚀的环境痕迹更明显 | **余绪稳定显形** |

**两条必须保留的设计**：

1. **霜效在活动日内触发。** 进入霜日时对在田植株判定；当日新栽植株从首次暴露时判定。每株每游戏日最多一次，记录暴露日与修正值。成熟待收也可受霜；采收入包时锁定品质。修正夹在最低档与该株品质上限之间，覆盖或熏烟须在暴露前生效。后台、失焦、关闭或手动暂停期间均不触发。
2. **霾天让余绪稳定显形。** 玩家可利用预报安排寻找余绪的行程。

雷造成的损坏必须可预防（避雷针、收纳设备），不得构成意外惩罚。

### 6.3 预报

**预报 100% 准确，不做概率。**

天气预报是排程工具，不是紧张感来源。

| 层级 | 视野 | 获取方式 |
| --- | --- | --- |
| 基础 | 7 天 | 起始即拥有（志局旧址的风向标） |
| 中级 | 14 天 | 建造气象台 |
| 高级 | 28 天（整季） | 建造观星台（后期） |

### 6.4 与地脉的关系

- 风向可改变地脉流向的表现；作物收获的数量、品质和掉落表不读取风向或风天临时变化。
- 雷雨会短期激活地脉，提升当日变异率
- 月相影响地脉涨落，进而影响鱼类出现与变异
- 地脉与天气的耦合只做正向加成，不做惩罚叠加

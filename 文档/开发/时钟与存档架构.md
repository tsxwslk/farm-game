# 架构：时钟与存档

**状态**：v0.1 框架
**范围**：技术选型、激活计时实现、日边界触发、存档结构、数据校验
**不包含**：具体模块划分与接口定义（待原型验证后补充）

---

## 1. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite + TypeScript | 与既有工程习惯一致，冷启动快 |
| 状态 | Pinia（或等价集中 store） | 整棵状态树可序列化，存档天然是 JSON |
| 持久化 | IndexedDB（idb） | 容量足够，支持结构化克隆 |
| 渲染 | DOM + CSS + 内联 SVG | 管理型游戏，UI 密集，不需要 Canvas 或游戏引擎 |
| 部署 | 静态托管 | 无后端，无运维 |

**明确不做**：Canvas 主循环、WebGL、游戏引擎、Service Worker 复杂缓存、后端与账号系统。

## 2. 时钟模型

### 2.1 核心：累计激活时长

游戏时间**不**从系统时间派生，而是从一个只增不减的计数器派生：

```
activeGameMinutes  // 只增不减，单位：游戏分钟
```

这个计数器是存档的核心字段之一。所有时间相关状态都从它算出来，不存在第二个时间源。

### 2.2 推进规则

每帧累加，**单帧增量必须钳制**：

```
delta = min(now - lastFrame, 250ms)
if (visible && focused && !paused) activeGameMinutes += delta / 1000 * speed
```

**为什么钳制**：标签页被浏览器节流、系统休眠恢复、rAF 中断等情况下，`now - lastFrame` 可能出现巨大的值。不钳制会导致玩家回来发现过了几十天。

### 2.3 暂停

| 事件 | 动作 |
| --- | --- |
| `visibilitychange` → hidden | 停止累加 |
| `visibilitychange` → visible | 重置 lastFrame，重新检查焦点与手动暂停 |
| `blur` / `focus` | 重置 lastFrame 并重算三项条件，恢复焦点时仍尊重手动暂停 |
| 手动暂停 | `paused = true` |

暂停不写入存档，只在运行时生效。

### 2.4 派生量

```
MIN_PER_DAY  = 1080      // 18 个可活动小时
DAY_START    = 360       // 06:00
DAYS_PER_SEASON = 28
SEASONS_PER_YEAR = 4

minuteOfDay = DAY_START + floor(activeGameMinutes % MIN_PER_DAY)
dayIndex    = floor(activeGameMinutes / MIN_PER_DAY)
seasonIndex = floor(dayIndex / DAYS_PER_SEASON) % SEASONS_PER_YEAR
yearIndex   = floor(dayIndex / (DAYS_PER_SEASON * SEASONS_PER_YEAR))
```

正常流速为 1。累计 1,079 分钟显示第 1 天 23:59；1,080 分钟显示第 2 天 06:00。成熟与加工时长统一用活动分钟，跨午夜实际走 1 分钟就累积 1 分钟。

### 2.5 存档时的处理

存 `activeGameMinutes` 一个数字即可完整还原时间。**不需要记录系统时间戳做对账**，因为时间根本不依赖系统时间。

附带好处：改系统时间、时区、夏令时、跨设备迁移都不影响游戏内时间。

## 3. 日边界触发

日边界由 `dayIndex` 的**变化**驱动，不依赖定时器：

```
for (day = lastDayIndex + 1; day <= dayIndex; day++) {
  applyDayOnce(day)  // 当天事件和 lastDayIndex 随同一快照提交
}
```

**必须支持一次跨多天**：倍率和测试步进共用推进函数，按换日边界切段：先用旧日天气计算已走的活动分钟，再处理新日天气、暴露、日事件，然后推进该日剩余分钟。同一日号的刷新只提交一次。

刷新顺序固定（对应[时钟季节与天气](../策划/时钟季节与天气.md)第 3 节）：天气 → 商店 → 委托 → 月相 → 动物 → 土壤 → 余绪显形。

**视觉表现**：刷新只发一个轻量提示事件，不阻断输入、不卸载场景。

## 4. 存档结构

### 4.1 顶层

```ts
{
  schemaVersion: number,
  savedAt: string,          // 仅用于展示，不参与逻辑
  activeGameMinutes: number,
  lastDayIndex: number,
  world: {
    weather: {...},
    soil: {...},
    plots: [...],
    species: {...},         // 已种植实例
    inventory: [...],
    ledger: {...},          // 首次收录、已获品质、上锚与稿酬记录
    economy: {...},
    buildings: [...],
    unlocks: {...}
  },
  settings: {...}
}
```

物志以条目 ID 保存首次收录记录。日刷新、库存消费与读档都沿用这份记录，点亮状态只从未收录转为已点亮。

### 4.2 版本迁移

**从第一天就必须有迁移机制**，否则第三次改数据结构就废档。

```
migrations: Record<number, (save: any) => any>
```

加载流程：读存档 → 逐版本链式迁移 → 校验 → 载入。迁移函数只做加法与改名，不做删除。

### 4.3 存档策略

| 时机 | 方式 |
| --- | --- |
| 手动保存 | 立即写快照 |
| 自动保存 | 每 3 分钟一次 |
| 页面隐藏前 | 写一次 |
| 关键节点 | 日边界、解锁完成、建筑落成 |

**外加**：一键导出 JSON 到本地文件，防清缓存丢档。导入时走同一套迁移链路。

## 5. 数据驱动与校验

所有物种、天气、建筑、区域均为**纯数据表**，代码只写规则。

**加载时必须校验**（schema 校验，如 zod 或手写校验器）：

- 开发环境：校验失败直接抛错，不静默容错
- 生产环境：跳过坏条目并记录，保证不白屏

**理由**：这个游戏的核心优势是"自己随便加内容"。如果手改数据能炸档，优势就变成了风险。

## 6. 渲染分层

| 层 | 内容 | 技术 |
| --- | --- | --- |
| 场景层 | 农场网格、地形、角色 | CSS Grid + 绝对定位 |
| 实体层 | 作物、建筑、动物 | 内联 SVG |
| UI 层 | 顶栏、背包、物志、建筑菜单 | 普通 DOM |
| 覆盖层 | 弹窗、tooltip、拖拽预览 | 绝对定位 + CSS 过渡 |

**SVG 复用**：同一图标在一屏出现多次时，用 `<symbol>` + `<use>` 引用，避免重复 DOM 节点。

**交付与加载。** 每个物品用稳定的资源键引用插画。美术在编辑器里手绘、用代码组装部件或导出整株都可以。首版把选定的图保存为静态 SVG，内容清单维护资源键到文件的映射。小规模直接用图片加载，浏览器复用同一 URL；同屏大量重复、经测量需要优化时可改为页面内符号复用。

示例清单（路径示意）：

```json
{"pea":{"seedling":"图像/豌豆幼苗.svg","vegetative":"图像/豌豆成株.svg","mature":"图像/豌豆成熟.svg","item":"图像/豌豆.svg"}}
```

物品表和存档引用稳定标识，文件名可调整。首屏只请求当前农田和可见背包图，翻开物志再请求该页缩略图；同一资源键合并请求。数量、品质、选中框由界面叠加。同物异色可选一个默认图合堆展示。收获物保持透明底，田间帧沿用固定根部锚点；多年生有待采果实时优先显示成熟图，采后再选生长或休眠图。

交付时检查清单中的文件、画布、必需阶段和引用是否完整。可选出土帧缺失时从幼苗开始；正式画面遇到坏文件时显示名称与占位图，保留条目和库存。每次发布更新变更资源的版本 URL，带走对应缓存。[美术交付规范](../美术/作物与物品美术规范.md)

[时钟与钱币测试台](../../prototype/时钟与钱币测试台.html) 可直接操作 1×、5×、20×、暂停、前进 1 小时、前进至次日 06:00，以及增加 100 / 1,000 文。本页使用独立的会话数据。正式游戏接入时，测试面板应调用与生产相同的时间推进与钱包记账函数；当来源为测试加款时，仅改变余额，跳过稿酬、首次收录和任务收入判定。

## 7. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 标签页节流导致时间跳跃 | 时间暴走 | 单帧增量钳制 250ms |
| 存档结构频繁变更 | 废档 | 迁移链 + 版本号，从第一天开始 |
| 图标资产数量膨胀 | 打包体积 | 按可见内容加载、复用静态文件 |
| 物志条目数增长（千级） | 渲染卡顿 | 虚拟滚动 + 分册懒渲染 |
| IndexedDB 被清 | 丢档 | 手动导出 + 定时提醒备份 |
